Why do I see #<BinaryExpr:0x00007afdea3d0208>?

This is pure Ruby behavior, not a parser bug.

What’s happening

When Ruby prints an object, it does this:

If the object has an inspect method → use it

Otherwise → print the default object reference

Right now:

NumberLiteral ✅ has inspect

VariableRef ✅ has inspect

BinaryExpr ❌ does NOT

So Ruby falls back to:

#<BinaryExpr:0x00007afdea3d0208>



class BinaryExpr < ASTNode
  def inspect
    "(#{left.inspect} #{op} #{right.inspect})"
  end
end


You now have:

✔ Real AST nodes

✔ Separation of parsing vs execution

✔ Correct operator precedence

✔ Statement boundaries



What happens now

Input:

print 1 + 2;


Parse flow:

expr → (Number(1) + Number(2))

; is consumed

Statement ends cleanly

Parser is happy 😌

Expected output shape:

(Number(1) + Number(2))


Right now, atom still evaluates things:

Integer → Ruby integer

String → variable lookup (var[name])

We will change it so that:

Numbers → NumberLiteral

Variable names → VariableRef

Parentheses → just forward the AST




You now satisfy:

✔ Arithmetic with correct precedence
✔ No evaluation in parser
✔ Full AST construction
✔ Program root node
✔ Clean separation parse vs execute

This fully addresses the most serious feedback comment.
